1. Executive Summary

This proposal presents the design and development of a Petty Cash Monitoring System for L.V. Ledesma Construction, Inc. The system addresses the challenges of manually tracking petty cash funds, expenses, and liquidation processes by providing a centralized, web-based platform with automated monitoring, threshold alerts, and formal report generation.

The system maintains a fixed petty cash fund of ₱30,000, automatically tracks expenses against the fund balance, triggers replenishment alerts at 30% utilization, and generates formal liquidation reports exportable to Excel. It is built using Laravel 13 (PHP), PostgreSQL, and is deployed on Render for cloud accessibility.

2. Problem Statement

Construction companies like L.V. Ledesma Construction, Inc. commonly manage petty cash funds for day-to-day operational expenses such as supplies, transportation, meals, and communication. The current manual process presents several challenges:

  • Lack of Real-Time Visibility: Fund balances and expense totals are not easily trackable, leading to overspending or delayed replenishment.
  • Manual Record-Keeping: Paper-based or spreadsheet tracking is prone to errors, data loss, and duplication.
  • Delayed Liquidation: Without automated alerts, liquidation reports are often prepared late, causing discrepancies in fund reconciliation.
  • No Audit Trail: Manual systems lack proper logging of who created, modified, or approved transactions.
  • Inefficient Replenishment: The process of requesting, approving, and disbursing replenishment funds is slow and lacks transparency.

3. Proposed Solution

A web-based Petty Cash Monitoring System that provides:

  • Real-time fund balance tracking with a fixed ₱30,000 target
  • Automated expense recording with balance deduction
  • 30% threshold auto-trigger for replenishment requests
  • Multi-step replenishment workflow (Request → Approve → Disburse)
  • Formal liquidation report generation with grouped expense items
  • Excel export and print-ready report formatting
  • Role-based access control (Admin / User)

4. Objectives

4.1 General Objective

To develop a web-based petty cash monitoring system that automates fund tracking, expense management, replenishment workflows, and liquidation reporting for L.V. Ledesma Construction, Inc.

  1. Implement a centralized fund management system with a fixed ₱30,000 petty cash target.
  2. Enable real-time expense recording with automatic fund balance updates.
  3. Provide automated 30% threshold alerts that trigger replenishment report creation.
  4. Develop a multi-step replenishment workflow with approval and disbursement tracking.
  5. Generate formal liquidation reports with grouped expense items and signature blocks.

5. Scope and Limitations

Scope

  • Petty cash fund creation, replenishment, and balance management
  • Expense recording with payee, category, cost code, particular, amount, and date
  • Automated 30% threshold detection and replenishment request generation
  • Replenishment request workflow: Create → Approve/Reject → Disburse
  • Liquidation report creation with auto-populated expense items
  • Expense status tracking (Open/Closed) linked to liquidation reports
  • Excel export of liquidation reports
  • Print-ready report formatting
  • User authentication and role-based access (Admin, User)

Limitations

  • Single-fund system (one ₱30,000 fund at a time)
  • No multi-currency support
  • No email/notification system (alerts are in-app only)
  • No mobile app (responsive web only)
  • No integration with accounting software
  • No receipt image upload

6.2 Dashboard

The dashboard provides a real-time overview including:

  • Four key metric cards: Total Funds, Total Balance, Total Spent, Pending Alerts
  • Pending replenishment requests table with Approve/Reject actions
  • Petty Cash Funds table with utilization progress bars and status badges
  • Recent Transactions table (10 most recent expenses)
  • Add Fund (Replenish) modal for quick fund additions

6.3 Fund Management

  • Target Balance: Fixed at ₱30,000
  • Add Fund: Increases current balance (replenishment)
  • Utilization Tracking: Progress bar with color-coded thresholds (green <30%, yellow 30-50%, red >50%)
  • Status Tracking: Active, To Liquidate, Pending

6.4 Expense Tracking

  • Fields: Payee, Category, Particular, Cost Code, Amount, Receipt #, Date
  • Real-time fund balance deduction upon expense creation
  • Balance Preview on edit showing +/- difference and projected fund balance
  • Expense status: Open (pending liquidation) / Closed (included in report)

6.5 Replenishment Workflow

30% Threshold Hit → Auto-Request Created → Admin Approves → Admin Disburses → Fund Restored to ₱30,000
  • Auto-triggered when total expenses ≥ ₱9,000 (30% of ₱30,000)
  • Manual creation available via Replenishments page
  • Status flow: Pending → Approved → Disbursed (or Rejected)
  • Disbursement restores fund balance to ₱30,000

6.6 Liquidation Reports

  • Auto-populated with all open expenses
  • Cash Received auto-filled with total liquidation amount
  • Items grouped by Cost Code and Particulars in the report view
  • For Return / (Reimbursement) auto-calculated
  • After creation, included expenses are marked as "Closed"
  • Signature blocks for Prepared By, Reviewed By, Verified By

6.7 Excel Export and Printing

  • Download as .xls file with company header, itemized table, totals, and signatures
  • Print-ready formatting optimized for A4 paper
  • Navigation bar hidden in print view

8. System Workflow

8.1 Complete Petty Cash Cycle

1. Fund Setup (₱30,000) → 2. Record Expenses → 3. 30% Threshold Alert → 4. Create Liquidation Report → 5. Approve & Disburse Replenishment → 6. Fund Restored

Step-by-Step Process:

  1. Fund Initialization: Admin creates/replenishes the petty cash fund to ₱30,000.
  2. Expense Recording: As expenses are incurred, they are logged into the system with payee, category, cost code, amount, and date. The fund balance is automatically reduced.
  3. Threshold Monitoring: The system continuously monitors total expenses. When they reach ₱9,000 (30% of ₱30,000):
    • A replenishment request is auto-generated
    • The user is redirected to create a liquidation report
  4. Liquidation Report: Admin creates a formal report with all open expenses, voucher numbers, and signature blocks. Expenses are marked as "Closed" after report creation.
  5. Replenishment Processing: Admin approves and disburses the replenishment request, restoring the fund to ₱30,000.
  6. Cycle Reset: The fund is restored and a new expense cycle begins.

10. Security Considerations

  • Authentication: Laravel's built-in session-based authentication with secure password hashing (bcrypt)
  • Authorization: Role-based middleware (AdminMiddleware) restricts sensitive operations
  • CSRF Protection: All forms include CSRF tokens
  • Input Validation: Server-side validation on all form inputs
  • SQL Injection Prevention: Eloquent ORM and parameterized queries
  • XSS Prevention: Blade template auto-escaping of output
  • Database Transactions: Critical operations wrapped in DB transactions for data integrity
  • Row Locking: SELECT ... FOR UPDATE on fund balance modifications to prevent race conditions
  • Session Security: Session regeneration on login, secure cookie handling
  • Environment Variables: Sensitive configuration stored in .env (not in version control)
